# D.PAO 数字梳妆台

面向手机浏览器的开瓶产品管理应用，延续原型的米白与酒红配色。使用 Vue 3 + Vite，依赖随构建打包，不依赖运行时 CDN。

## 本地开发

需要 Node.js 22 或 24。

```sh
npm ci
npm run dev
```

```sh
npm test
npm run build
```

## 使用流程

只填产品名称即可收录。开封日期可以选择今天、确切日期、大概日期或稍后补充；照片、分类、瓶身 PAO 月数和余量均可稍后填写。未确认的日期和期限不会被默认值替代，大概日期的倒计时使用「约」和「预计」标记。

首页按需要处理、临近期限、到期复查、待补充及日常使用分组。同一产品只出现在一个分组。超期记录优先提示检查和停用，临期且余量较多时提示留意使用安排，不预测消耗速度。

余量支持「还有很多／剩一半／快见底／看不清」，也可展开百分比滑条。复查可选 7、14、30 天后或不安排。空瓶评价可跳过，之后在「使用档案」中补写；停用另记原因，保留停用时余量，并与空瓶分开筛选。历史空瓶可补登并填写归档日期。

自定义分类直接输入。照片自动缩放至最长边 640px，以减少本地存储占用。

数据仅保存在当前站点、当前浏览器的 localStorage。沿用 `dpao_data_v4` 并兼容旧余量格式；更换域名或端口不会自动带入旧站点数据。请在原站点导出后，在本应用中导入。备份支持原始记录数组或本应用导出的 JSON。导入会替换现有数据并要求确认。

复查是应用内日期提示，需要用户再次打开页面，不包含后台推送、邮件或系统通知。PAO 以品牌和包装说明为准，未标识产品需自行查证；不建议通过转作其他用途继续使用超期产品。

## 验证

`npm test` 覆盖月末和闰年的期限计算、日期边界、未知信息保留、模糊期限表达、首页分组、旧数据兼容及备份校验。浏览器端测试位于 `tests/browser.spec.js`，先启动开发服务器，再运行 `npx playwright test`（默认使用 `/usr/bin/chromium`，可用 `CHROMIUM_PATH` 指定其他 Chromium 可执行文件）。

## 更新已有版本

更新前先在旧页面导出备份。下载最新版源码到新文件夹，在旧终端按 Control+C 停止服务器，再进入新项目目录执行 `npm ci` 和 `npm run dev`。尽量沿用原访问地址及端口；浏览器记录按站点隔离，若记录未显示，可导入此前备份。代码更新不会自动同步电脑与手机的数据。

## 无需安装的整理模式原型

新增独立页面：`prototypes/dpao-review.html`，可以直接在浏览器中打开。也可下载 `prototypes/DPAO-demo.zip`，解压后双击 `DPAO-demo.html`。这是独立的交互评审版本，真实资料查询尚未接入，数据与原应用隔离。详见 `prototypes/README.md`。
